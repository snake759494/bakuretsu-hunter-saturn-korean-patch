# 기술 설명

## 디스크

트랙 1은 MODE1/2352 ISO9660입니다. `tools/cdimg.py`가 섹터 헤더·EDC/ECC를 다시 계산하며 파일을 제자리에 덮어씁니다. 바뀐 파일이 원래 섹터 수를 넘으면 디스크 끝에 붙이고 디렉터리 항목을 고치지만, v1.0에서는 모든 파일이 원래 크기 안에 들어가 디스크 크기가 원본과 같습니다. 트랙 2(음악)는 건드리지 않습니다.

## 장면 대사

각 장면은 `PRG/MEN<장면>.BIN`(SH-2 코드와 메시지)과 `DAT/*.DAT`(그림·글꼴)로 이루어집니다.

- 메시지는 16비트 빅엔디언 글리프 번호 배열입니다. `0xFFFE` 줄바꿈, `0xFFFC` 페이지 넘김(버튼 대기), `0xFFFF` 끝, `0` 공백.
- 글꼴은 장면마다 그 장면에 쓰인 글자만 16×16 4bpp(0x80바이트)로 DAT 안에 들어 있고, 장면 시작 때 VDP2 VRAM으로 복사됩니다. 그래서 원문 문자 코드표가 없고, 원문 확인은 글리프 그림을 대조해야 했습니다.
- 한글은 장면마다 쓰는 글자가 원래 칸보다 많아질 수 있어, 글리프를 **1bpp(0x20바이트)**로 넣고 작은 SH-2 확장 루틴(`tools/expand.py`)을 DAT의 원래 글꼴 자리 앞에 둡니다. 원래 복사 루틴(0x0602FBBC) 호출을 이 루틴으로 바꿔, VRAM 글꼴 영역으로 갈 때만 1bpp→4bpp로 펼치고 나머지는 원래 루틴으로 넘깁니다. 장면당 최대 383자.
- 메시지는 MEN 파일의 원래 메시지 영역에 다시 배치하고, 넘치는 것은 DAT 글꼴 영역의 남는 곳에 둡니다. MEN 안의 메시지 포인터(`scan2.json`의 `ptrs`)를 새 주소로 고칩니다.
- `M`이 붙은 장면(예: `1_01M`)은 같은 DAT를 쓰는 변형이라 같은 번역을 씁니다.

## 이름표

대화창 위 캐릭터 이름은 DAT 안의 16×16 4bpp 타일 3칸 묶음입니다(`names.json`의 `groups`). 갈무리9로 그리고, 3칸에 넘치는 이름은 갈무리7로 그립니다(`tools/kname.py`).

## 그림 글자

- `DAT/TIT_DT.BIN`: 타이틀·옵션·파일 메뉴의 4bpp 스프라이트. 버튼은 글자를 지우고 같은 팔레트 번호로 다시 그립니다(`tools/kmenu.py`). 232×72 8bpp 로고는 그림을 살리고 오른쪽 아래에 갈무리7 「폭렬헌터」를 테두리와 함께 얹습니다(`tools/ksub.py`).
- `DAT/SAVE.BIN`·`DAT/LOAD.BIN`: [4바이트 헤더][VDP2 문자 데이터 8bpp][팔레트]. 화면 맵(`loadmap.json`)을 따라 셀을 찾아 「세이브 중」을 그리고, 로고 자막은 화면에 한 번만 쓰이는 타일에만 그립니다(공유 타일에 그리면 화면 곳곳에 반복되기 때문). `tools/kload.py`.
- `DAT/SLOT_DT.BIN`: 슬롯 배틀 「勝」「利」「敗」「北」 64×64 4bpp 스프라이트를 「승」「리」「패」「배」로 다시 그립니다(`tools/kslot.py`).

## 조사 범위

- 실행 코드(PRG)에서 화면에 나오는 Shift-JIS 문자열을 찾지 못했습니다. 메뉴 글자는 모두 그림입니다.
- 오프닝 동영상(`OPEN.CPK`, Cinepak)의 크레디트는 손대지 않았습니다.
- 각 장 폴더의 캐릭터·배경 그림은 플레이 중 본 장면에서 글자가 없었습니다.

## 테스트 도구

`tools/emu.py`·`srv.py`·`c.py`·`play.py`는 에뮬레이터를 백그라운드로 띄워 입력을 보내고 화면을 캡처하는 개인 테스트용 도구입니다. `tools/mkt.py`는 장면 순서표를 바꿔 특정 장면부터 시작하는 테스트 이미지를 만듭니다.
